# ing 系列软件开发指南

> 依据：ingfy 3.0.0 之后的代码和这几个月的开发过程。整理于 2026-11-19。
> 用法：开一个新软件（比如 ing番茄钟）时，把这份指南和《ingfy 设计风格》一起交给 Claude，再说要做什么。
> 标了 **【建议】** 的是我给整个系列提的建议，还没在 ingfy 里用过，你可以改；没标的都是 ingfy 现在的实际做法。

---

## 1. 这个系列是什么

- **名字**：`ing` + 功能，例如 ingfy、ingtranslate、ing番茄钟。
- **平台**：Windows 10 / 11（64 位）的桌面小软件，一个软件只做一件事。
- **长相**：深紫夜色 + 液态玻璃 + 胶囊形控件 + Apple 式动效。同一个系列放在一起要像一家人。
- **数据**：默认都存在用户自己的电脑上，不建自己的账号和服务器。需要联网的功能（查歌词、翻译这类）只把必须的内容发给对方的服务；需要第三方账号（比如 Spotify）时，只走对方的官方登录。
- **发布**：源码放 GitHub，安装包挂在 Release 上，软件自己检查更新。
- **署名**：Made by Ingram & Claude。

---

## 2. 技术栈

| 部分 | 用什么 | 版本（ingfy 现在的） |
| --- | --- | --- |
| 外壳 | Tauri | 2 |
| 界面 | React + TypeScript | React 18.3，TypeScript 5.5 以上 |
| 打包前端 | Vite | 5.4，开发端口固定 1420 |
| 后端 | Rust | edition 2021 |
| 包管理 | pnpm | Node.js 20 以上 |
| 安装包 | NSIS | 装在当前用户下，简体中文 + 英文 |

**不用的东西**：界面组件库、CSS 框架、状态管理库、路由库。界面全部手写，样式全在一个 `styles.css` 里。依赖越少，软件越小，也越不容易坏。

**Tauri 插件**（按需要加）：`global-shortcut`（全局快捷键）、`autostart`（开机自启）、`single-instance`（只允许开一个）。托盘用 Tauri 自带的 `tray-icon`。

**Rust 正式版的编译设置**（体积小）：

```toml
[profile.release]
codegen-units = 1
lto = true
opt-level = "s"
strip = true
```

**TypeScript 开得很严**：`strict`、`noUnusedLocals`、`noUnusedParameters` 都开着，而且 `pnpm build` 会先跑 `tsc`。所以**一个没用到的变量就会让打包失败**，交付前必须过一遍类型检查。

## 3. 开一个新软件的步骤

最省事的办法是从 ingfy 复制骨架，再把名字换掉。

1. **定名字和一句话介绍**。例如"ing番茄钟：液态玻璃风格的番茄钟"。
2. **建文件夹和仓库**：`E:\<软件名>`，GitHub 上建同名仓库。
3. **从 ingfy 拿这些文件**（见第 4 节的结构）：`package.json`、`vite.config.ts`、`tsconfig.json`、`index.html`、`.gitignore`、`src-tauri/` 的配置文件、`src/styles.css` 里通用的部分、`src/lib/` 和 `src/components/` 里通用的几个文件。
4. **把下面这些名字全部换掉**，一个都不能漏：

| 位置 | ingfy 里的值 | 新软件 |
| --- | --- | --- |
| `package.json` 的 `name` | `ingfy` | 新名字 |
| `Cargo.toml` 的 `name`、`description`、`[lib] name` | `ingfy`、`ingfy_lib` | 新名字、`新名字_lib` |
| `tauri.conf.json` 的 `productName`、窗口 `title`、`publisher`、`copyright`、`category`、两段说明 | ingfy… | 新的 |
| `tauri.conf.json` 的 `identifier` | `com.nige.lyrics`（早期叫"霓歌"时留下的） | **【建议】** `com.ingram.<软件名>` |
| 设置在 localStorage 里的键 | `nige.settings`（同样是旧名字留下的） | **【建议】** `<软件名>.settings` |
| 检查更新的地址 | `api.github.com/repos/Ingram5656/ingFY/releases/latest` | 新仓库 |
| 托盘的 id、安装包文件名、`taskkill` 的进程名 | `ingfy` | 新名字 |
| 图标 | `src-tauri/icons/` | 新图标（见下一条） |

   `identifier` 决定数据文件夹（`%APPDATA%\<identifier>`）。**发布以后不要改**，改了老用户的设置就找不到了。

5. **图标**：准备一张 1024×1024 的 PNG，运行 `pnpm tauri icon 图标.png`，会生成 `icons/` 里的全部尺寸。
6. **先做能跑的最小版本**：一个主窗口、能用的核心功能、设置面板、托盘。跑通 `pnpm tauri dev` 以后再加别的。
7. **写 README 和 CHANGELOG**，版本从 `0.1.0` 开始，觉得可以给别人用了再发 `1.0.0`。

## 4. 项目结构

```
<软件名>/
  package.json  vite.config.ts  tsconfig.json  index.html  .gitignore
  README.md  CHANGELOG.md  LICENSE
  docs/                      截图、设计风格、这份指南
  scripts/                   打包脚本等
  src-tauri/
    Cargo.toml  tauri.conf.json  build.rs
    capabilities/default.json   每个窗口能用哪些权限
    icons/
    src/main.rs              入口，只调 lib.rs
    src/lib.rs               命令、托盘、快捷键、窗口、更新
    src/<功能>.rs            每块功能一个文件
  src/
    main.tsx                 按窗口标签决定显示哪个界面
    styles.css               全部样式
    views/                   一个窗口一个文件
    components/              面板、菜单、控件
    lib/                     不带界面的逻辑：设置、语言、动效、各功能
```

**可以直接搬到新软件的通用文件**（ingfy 里已经有）：

| 文件 | 干什么 |
| --- | --- |
| `lib/settings.ts` 的框架 | 设置的读、存、跨窗口同步（见 5.1） |
| `lib/i18n.ts` + `i18n-en.ts` | 中英文界面（见 5.3） |
| `lib/motion.ts` | 交叉淡化、分段控件滑块、闲置检测、拖动排序 |
| `lib/shortcuts.ts` | 自定义全局快捷键：录制、冲突、占用提示 |
| `lib/cache.ts` | 清理缓存 |
| `lib/palette.ts` | 从图片取色、调成发光色、深色底 |
| `lib/bgvideo.ts` | 把大文件（视频）存进 IndexedDB |
| `components/Presence.tsx` | 让面板关掉时有退场动画 |
| `components/Sheet.tsx` | 居中的对话框 |
| `components/SettingsPanel.tsx` 的框架 | 左边分类、右边分组的设置面板，和里面的开关、滑块、选项块 |
| `styles.css` 里的玻璃、按钮、分段控件、开关、设置面板 | 见《ingfy 设计风格》 |

**【建议】** 做到第三个软件时，把这些通用文件抽成一个单独的仓库（比如 `ing-kit`），每个软件复制或引用同一份。现在先复制，不急着抽。

## 5. 前端的写法

### 5.1 设置

- 所有设置放在一个 `Settings` 类型里，每一项上面写一行注释说明是什么。
- `DEFAULT_SETTINGS` 给每一项默认值。读的时候用 `{ ...默认值, ...存下来的 }` 合并，这样**以后加新设置，老用户自动拿到默认值**，不用写迁移。
- 改名、删选项这类不兼容的改动，在 `load()` 里写一句兼容，并注明是哪个版本改的。
- 存在 localStorage 的一个键里。改设置时存一次，再发一个 `settings-changed` 事件，其他窗口收到后同步。
- 组件里只用 `const [settings, update] = useSettings()`，改的时候 `update({ 某一项: 新值 })`。
- localStorage 放不下大东西。图片先缩小再存；视频存 IndexedDB。存不下要告诉用户，不能悄悄失败。

### 5.2 多个窗口

- 所有窗口加载同一个页面，`main.tsx` 里按窗口标签（`getCurrentWindow().label`）决定显示哪个界面。
- 小窗口在 `tauri.conf.json` 里写 `"create": false`，第一次用到时才创建，省内存。
- 窗口之间不直接互相调用，只通过事件和设置同步。
- 每个窗口要用的权限写进 `capabilities/default.json`，没写的调用会被拒绝。
- 悬浮在桌面上的小窗口：`decorations: false`、`transparent: true`、`alwaysOnTop: true`、`skipTaskbar: true`，位置和开关状态要记住。

### 5.3 界面语言

- **写代码时直接用中文原文当 key**：`t("播放列表")`。带变量的写 `t("还剩 {n} 分钟", { n: 3 })`。
- 英文放在 `i18n-en.ts` 的一张表里。每加一句中文，就在表里补一句英文。
- 后端返回的提示也是中文，显示前用 `tMsg()` 翻译。
- 用到 `t()` 的组件要调一次 `useLang()`，切换语言时才会刷新。

### 5.4 布局

- 主界面按固定的设计尺寸排版（ingfy 是 1440×900），再整体等比缩放到窗口大小。好处是任何窗口尺寸下比例都一样，不用到处写响应式。
- 鼠标 3 秒不动，控件滑出画面、光标隐藏；有面板开着或正在拖东西时不收。

### 5.5 面板和动效

- 面板的显示和隐藏包一层 `<Presence show={...}>`，关掉时才有退场动画。
- 对话框用 `Sheet`。破坏性操作（删除、清空）要再确认一次，按钮上写清楚会发生什么。
- 进场：从 `scale(1.025)` 加透明落到位。退场：缩小一点淡出。不做硬切。
- 系统开了"减弱动态效果"时，动画缩到几乎没有，闪烁的效果改成柔和的。

### 5.6 会动的画面（画布、显卡）

ingfy 的拾音灯、3D 场景、助眠模式的雨都属于这一类。规矩：

- **限帧**：一般 30 帧，最多 60 帧。
- **没东西可画就停**：画面静止时循环空转，不重画。
- **窗口藏起来、最小化时暂停**，视频也暂停。
- **画布像素有上限**：高分屏上不按满像素画。
- **机器吃力时自动降帧**。
- **用显卡的功能要有退路**：显卡起不来时换简单画法，不能白屏。
- 每秒更新几十次的东西（进度、歌词）单独放一层，只重画跟它有关的那几块，不带着整页重画。

## 6. 后端（Rust）的写法

- **一块功能一个文件**，`lib.rs` 只放命令、托盘、快捷键、窗口、更新这些"接线"的东西。
- **命令**用 `#[tauri::command]`，可能失败的返回 `Result<T, String>`，错误信息写成能直接给用户看的中文，例如"没有正在播放的媒体"。
- **耗时的事**（联网、读文件）写成 `async`，别卡住界面。
- **联网**用 `reqwest` + `rustls-tls`，不带系统的 OpenSSL。请求失败和"没有结果"要分开返回，界面上才能分别提示。
- **托盘**：左键点图标打开主窗口，右键菜单里有退出。
- **关主窗口**：第一次问一下是留在托盘还是退出，之后照选的来，设置里能改。
- **只开一个**：再开一次时把已有的窗口叫出来。
- **开机自启**：启动参数带 `--autostart`，这样自启时不弹主窗口。
- **全局快捷键**：给默认组合，允许用户改；被别的软件占用时要提示。
- **检查更新**：读 GitHub 仓库最新的 Release，版本号更高、附件里有 `.exe` 安装程序时，设置按钮上出小红点，用户点"立即更新"下载并安装。
- **用户数据放哪**：设置在网页内核的存储里；登录信息这类单独的文件放 `%APPDATA%\<identifier>\`；导出给用户的文件放"图片\<软件名>"或"文档\<软件名>"。

## 7. 设计

完整规范见《ingfy 设计风格》（`E:\ingfy\docs\设计风格.md`）。整个系列必须一致的是下面这些：

- **底色**：深紫夜色 `#1A1238`，整体深色。
- **材质**：只有玻璃，分薄玻璃（顶栏、工具条、小按钮）和厚玻璃（设置、弹出面板）两档。不加别的材质。
- **形状**：按钮、分段控件、开关都是胶囊；面板是大圆角。不用直角。
- **投影**：带紫调的深色，不用纯黑。
- **字体**：中文 Noto Sans SC，拉丁文和数字 Sora。
- **动效**：默认曲线 `cubic-bezier(0.32, 0.72, 0, 1)`，快出慢停；滑块和让位用带一点回弹的曲线。
- **设置面板**：左边分类、右边分组，像 iOS 的设置。**分组下面不放小字说明**；一个选项的名字要自己说得清楚。
- **内容是主角**：控件收在玻璃胶囊里，闲置时退场。

**颜色从哪来，每个软件自己定。** ingfy 的颜色来自专辑封面，没有固定的品牌色。别的软件没有封面，需要另找一个"会变的颜色来源"：

- **【建议】** ing番茄钟：专注一套颜色、休息一套颜色，切换阶段时 1.2 秒过渡。
- **【建议】** 没有合适来源时，用系列的默认调色板（粉到紫：`#FF9BB3` `#FF6F91` `#E3579E` `#C34A9F` `#9B47B4` `#6F48C6`），并让用户在几组预设配色里选。

## 8. 文字

- 按钮写它做的事："换一个视频""删除视频"，不写"确定""提交"。
- 同一件事从头到尾一个叫法。菜单里叫"助眠模式"，设置里、弹窗里也叫"助眠模式"。
- 出错时说清楚发生了什么、该怎么办："视频太大了，请选 400 MB 以内的"。不说"操作失败"。
- 空着的地方告诉用户能做什么："点击选择"。
- 做不到的功能直接置灰并让人看得出原因（比如晴天时"打雷"开关是灰的），不要点了没反应。
- 版本日志和 README 用大白话，写用户看得见的变化，不写内部实现。

## 9. 交付前的检查

Claude 这边没法在真机上编译和运行，所以每次交付分两步：

**Claude 做的**
1. 类型检查（`tsc`），不能有新的错误。
2. 在模拟环境里跑界面：把 Tauri 的接口换成假的，用无头浏览器截图，把主要流程点一遍。
3. 明确告诉你哪些验证过、哪些没法验证。通常没法验证的是：Rust 能不能编译、真显卡上的流畅度、声音、系统托盘和快捷键。

**你做的**
1. `pnpm tauri dev` 看实际效果。
2. 改了 Rust 或 `tauri.conf.json` 要停掉重开。
3. 有问题截图或录屏发回来，比文字描述快得多。

**收到别人的问题反馈时，先查是不是真的，再动手改。**

## 10. 版本和发布

**版本号**：`主.次.修`。修 bug 加第三位，加功能加第二位，大改版加第一位。

**平时**
- 每做完一件事提交一次，提交说明用一句中文写改了什么，例如"助眠模式：音乐暂停时不打雷"。
- 同时在 `CHANGELOG.md` 的"未发布"下面记一条。
- **没说要发布，就不推送、不改版本号。**

**发布一个版本**
1. 改版本号，三处一致：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`（`Cargo.lock` 会跟着变）。
2. 把 CHANGELOG 里"未发布"的内容挪到新版本下，写上日期。README 里有变化的地方一起改。
3. **用 `scripts\build-release.cmd` 打包**，不要直接 `pnpm tauri build`。直接打包的话，`.exe` 里会带上 `C:\Users\<你的用户名>\...` 这样的路径。这个脚本会先关掉正在运行的软件，打包时把这段路径抹掉，打完再检查一遍并告诉你结果。新软件要把脚本里的 `ingfy.exe` 换成自己的名字。
4. 推送到 GitHub，新建 Release：标签写 `v` 加版本号，把 `<软件名>_x.y.z_x64-setup.exe` 拖进附件，说明直接贴 CHANGELOG 里这一版的内容。

## 11. 隐私和安全

发布前逐条过一遍：

- [ ] 代码和提交记录里没有密码、密钥、令牌。**Client Secret 永远不进代码**，需要登录的服务用不带密钥的方式（Spotify 用的是 PKCE）。Client ID 是公开信息，可以放。
- [ ] 代码、README、提交记录里没有你的邮箱、真名、电脑用户名、本机路径。
- [ ] `.exe` 里没有本机路径（用第 10 节的打包脚本，看到 `[OK]` 才发布）。
- [ ] 仓库里只有源码和必要的项目文件。`node_modules`、`dist`、`src-tauri/target`、日志都在 `.gitignore` 里。
- [ ] 截图和宣传片里没有露出账号、邮箱、桌面上别的东西。
- [ ] 用户的登录信息只存在他自己电脑的 `%APPDATA%` 里，不上传。

## 12. README 和宣传

**README 的顺序**（照 ingfy 的来）：一句话介绍和截图 → 目录 → 功能 → 下载安装 → 使用说明 → 快捷键 → 常见问题 → 从源码运行 → 打包与发布 → 项目结构 → 致谢 → 许可证。

**宣传片的规矩**（做 ingfy 宣传片时定下的）
- 先写台本，你看过再动视频。
- 字幕卡片上不加句号。
- 开头的声音不要尖。
- 不出现"全新""更新"这类说法。
- 画面不加任何模糊效果。
- 配乐从头放，不在中间剪断，结尾渐弱。
- 画面里出现软件界面时，进度和内容要对得上配乐的时间。
- 片尾署名 Made by Ingram & Claude。

## 13. 踩过的坑

| 坑 | 怎么办 |
| --- | --- |
| 打包报"拒绝访问" | 软件还在运行（包括托盘里）。先 `taskkill /IM <软件名>.exe /F` |
| `pnpm install` 提示构建脚本被忽略 | 跑一次 `pnpm approve-builds`，允许 `esbuild` |
| 一个没用到的变量让打包失败 | `tsc` 开了 `noUnusedLocals`。交付前过类型检查 |
| `.exe` 里带着电脑用户名 | 用 `build-release.cmd` 打包 |
| 大图片、视频存不进 localStorage | 图片先缩小；视频存 IndexedDB |
| 开发时效果跑两遍 | React 的 StrictMode 会把每个效果装两次。用到画布、显卡、声音的地方，卸载时要收干净，再装一次也不能出错 |
| 重启后第一次没声音 | 浏览器内核要等用户点过一下才让出声。点一下窗口就好；别把重要的提示只放在声音里 |
| 切歌的一瞬间被当成"暂停" | 状态短暂跳变的地方，等两三秒还没恢复再当真 |
| 画布上反复"淡一点"淡不干净 | 画布每个点只有 256 级，每次淡得太少会卡在一个很浅的值上。每次淡多一点、隔久一点 |
| 非官方接口（歌词源等）随时会变 | 至少两个来源，一个不行换另一个；连不上和没结果分开提示 |
| 推送标签被拒绝 | 在 GitHub 网页上建 Release 时顺便建标签 |

## 14. 例子：ing番茄钟可以怎么起步

**【建议】** 下面只是照这份指南推出来的一个起点，功能由你定。

- **窗口**：主窗口（大号倒计时，背景是会随阶段变色的流体色块）；一个悬浮小窗口（像 ingfy 的灵动岛，显示剩余时间，可锁定穿透）；托盘。
- **直接复用**：设置框架、语言、动效、快捷键、检查更新、托盘和关窗口的逻辑、开机自启、玻璃样式和设置面板。
- **要新写的**：计时本身（放在 Rust 里，窗口关了也照走）、阶段切换、到点提醒、统计。
- **设置面板的分类**：计时（专注、短休息、长休息各多久，几轮一次长休息）、提醒（声音、通知）、外观（背景、配色）、悬浮窗、快捷键、通用（语言、开机自启、关窗口时怎么办、检查更新）。
- **默认快捷键**：开始 / 暂停、跳过这一段、显示 / 隐藏悬浮窗。
- **第一个版本只做**：计时、阶段切换、到点提醒、托盘、设置。统计和悬浮窗放到后面的版本。
